FEATURE: Somatic Practice Push Notification & In-App Nudge
Read the entire spec before writing any code. This feature has three distinct components: the push notification system setup, the somatic engagement detection logic, and the in-app banner. All three must work independently — the banner shows even if the user has declined push notification permission.

PART 1 — PUSH NOTIFICATION INFRASTRUCTURE
1.1 Implementation
Use the Web Push API with a service worker. Do not use any third-party push notification service — implement natively.
Create the following files if they don't exist:
client/public/sw.js          — service worker
client/src/lib/push.ts       — push subscription utilities
1.2 Service worker (sw.js)
javascriptself.addEventListener('push', function(event) {
  if (!event.data) return;
  
  const data = event.data.json();
  
  const options = {
    body: data.body,
    icon: '/icons/icon-192.png',
    badge: '/icons/badge-72.png',
    tag: data.tag || 'paojilhuasca',
    renotify: false,
    requireInteraction: false,
    data: {
      url: data.url || '/'
    }
  };
  
  event.waitUntil(
    self.registration.showNotification(data.title, options)
  );
});

self.addEventListener('notificationclick', function(event) {
  event.notification.close();
  
  event.waitUntil(
    clients.matchAll({ type: 'window' }).then(function(clientList) {
      const url = event.notification.data.url;
      
      for (const client of clientList) {
        if (client.url === url && 'focus' in client) {
          return client.focus();
        }
      }
      
      if (clients.openWindow) {
        return clients.openWindow(url);
      }
    })
  );
});

Implement the following functions:

// Unsubscribe user from push

```

`subscribeToPush` must:
1. Check if service workers and push are supported — return false silently if not
2. Register the service worker if not already registered
3. Call `Notification.requestPermission()`
4. If granted, call `registration.pushManager.subscribe()` with `userVisibleOnly: true` and the VAPID public key
5. Send the resulting subscription object to `POST /api/push/subscribe`
6. Return true on success, false on any failure

Never throw errors to the UI from this function — catch everything and return false.

**PART 2 — PERMISSION REQUEST FLOW**

**2.1 When to ask**

Do NOT request push permission on first app open. Do NOT request during auth.

Request permission on the screen immediately after the ceremony date onboarding (the last onboarding screen before home). This is the correct moment — the user has just made a commitment by entering their ceremony date and is in a receptive state.

If the user skipped onboarding (pressed "Skip for now"), request permission on their third app open instead. Track app open count in localStorage as `app_open_count`.

**2.2 Permission request screen**

Full screen interstitial, same visual style as onboarding screens. Shows only once — controlled by `push_permission_asked` boolean on user record. Set to true immediately when this screen is shown, before user responds.

Icon: a simple bell SVG, sage green, centered.

Title:
*"Gentle reminders"*

Body text:
*"We keep notifications minimal — only when your practice might need a nudge. Never marketing, never noise."*

Two buttons:
- *"Yes, remind me"* (primary) — calls `subscribeToPush()`, proceeds to home
- *"Not now"* (text link) — proceeds to home, does not ask again

If `subscribeToPush()` returns false (permission denied by browser before our screen even showed, or unsupported), skip this screen entirely and set `push_permission_asked` to true silently.

**PART 3 — SOMATIC DETECTION LOGIC**

**3.1 The condition**

A user is flagged for somatic nudge when ALL of the following are true:

- `somatic_practice_completed` is false (user has never completed a practice in the somatic category)
- User has at least 3 journal entries logged total
- At least 5 days have passed since the user's first journal entry
- `somatic_nudge_sent_at` is null OR more than 7 days have passed since last nudge

**3.2 Where this runs**

Run as a daily server-side cron job at 09:00 local time (use UTC+user timezone if stored, otherwise UTC). The cron job:

1. Queries all users matching the somatic nudge condition
2. For each matching user with a valid `push_subscription`, sends the push notification
3. Updates `somatic_nudge_sent_at` to now for each user processed
4. Logs the count of notifications sent

**3.3 Somatic practice tracking**

When any practice is completed, check if its category is `somatic`. If yes, set `somatic_practice_completed` to true on the user record. This is permanent — once set to true, the nudge condition can never be true again for this user.

4.2 Sending from server
typescriptasync function sendSomaticNudge(userId: string): Promise<void> {
  const user = await getUserWithSubscription(userId);
  
  if (!user.push_subscription) return;
  
  const payload = JSON.stringify({
    title: "Your body is part of this too",
    body: "Integration doesn't only happen in the mind. There's a somatic practice waiting for you — it takes 5 minutes.",
    tag: "somatic-nudge",
    url: "/practices?category=somatic"
  });
  
  try {
    await webpush.sendNotification(
      user.push_subscription,
      payload
    );
    
    await updateUser(userId, { 
      somatic_nudge_sent_at: new Date() 
    });
    
  } catch (error: any) {
    // Subscription expired or invalid — clean it up
    if (error.statusCode === 410 || error.statusCode === 404) {
      await updateUser(userId, { push_subscription: null });
    }
    // Log other errors but do not throw
    console.error(`Push failed for user ${userId}:`, error.message);
  }
}

PART 6 — GLOBAL NOTIFICATION THROTTLE
This rule applies to all push notifications across the entire app, not just this feature.
Maximum one push notification per user per day, regardless of how many triggers are active.
Implement a notifications_sent_today check before any push send:
typescriptasync function canSendPushToday(userId: string): Promise<boolean> {
  const lastSent = await getLastNotificationSentAt(userId);
  if (!lastSent) return true;
  
  const hoursSinceLastSent = 
    (Date.now() - lastSent.getTime()) / (1000 * 60 * 60);
    
  return hoursSinceLastSent >= 20; // 20-hour window, not strict 24h
}
```

Add to users table:
```
last_notification_sent_at    timestamp, nullable
```

Update this timestamp after every successful push send, regardless of notification type.

If multiple notification types would fire on the same day for a user, use this priority order:

1. Crisis/red flag alert (highest)
2. Phase transition reminder
3. Somatic nudge
4. Streak reminder (if implemented later)

Only the highest priority pending notification fires. Lower priority ones wait until the next eligible day.

**PART 7 — API ENDPOINTS**
```
POST /api/push/subscribe
     body: { subscription: PushSubscription }
     → saves subscription to user record
     → returns { success: boolean }

POST /api/push/unsubscribe  
     body: {}
     → clears subscription from user record
     → returns { success: boolean }

GET  /api/push/status
     → returns { 
         subscribed: boolean,
         permission_asked: boolean,
         somatic_nudge_eligible: boolean
       }

POST /api/push/send-somatic-nudge
     → internal cron endpoint, protected with a cron secret header
     → not callable from client
     → triggers the full somatic nudge job
```

Protect the cron endpoint with a `X-Cron-Secret` header check against an environment variable `CRON_SECRET`. Return 401 if missing or incorrect.

PART 9 — CONSTRAINTS

Never send more than one push notification per user per day
Never send push notifications between 21:00 and 08:00 user local time — if the cron fires in that window, queue the send for 09:00
If push_subscription returns a 410 or 404 from the push service, immediately delete the stored subscription — it is expired and will never work again
The in-app banner must work even if push notifications are declined or unsupported
Do not show any push notification UI to users on browsers that do not support the Push API — check 'serviceWorker' in navigator && 'PushManager' in window before rendering any notification-related UI
The somatic nudge must never fire for a user who has already completed any somatic practice, even if somatic_nudge_sent_at would otherwise allow it
