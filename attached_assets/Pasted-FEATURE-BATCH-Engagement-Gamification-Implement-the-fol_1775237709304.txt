```
**PART 5 — TECHNICAL REQUIREMENTS**

**5.1 Idempotency**

Every seed-awarding action must be idempotent. Check `seeds_history` before awarding to prevent double-awards on retry or network failure. Use action + date (or action + entry ID) as the deduplication key.

**5.2 Server-side only**

No seed logic on the client. All awards go through a single server function `awardSeeds(userId, action, metadata)` that: validates the action is legitimate, checks idempotency, inserts to `seeds_history`, updates `seeds_total`, recalculates `plant_stage`, checks badge conditions, unlocks any newly earned badges, returns the updated state to the client.

**5.3 Badge check on every award**

After every seed award, run the full badge eligibility check for that user. Badge conditions are cheap to evaluate — run all 8 every time rather than trying to be clever about which ones to check. Newly unlocked badges are returned in the `awardSeeds` response so the client can show the unlock animation.

**5.4 API endpoints needed**
```
GET  /api/gamification/status        → seeds_total, plant_stage, badges_unlocked, seeds_to_next_stage
GET  /api/gamification/history       → seeds_history array (paginated)
POST /api/gamification/award         → internal only, called by other feature handlers
The /award endpoint should not be callable directly from the client — only invoked internally by other server actions (journal submit, practice complete, etc.).

PART 6 — CONSTRAINTS

Seeds are never deducted. No penalties, no losses, no streak shame.
Never show a leaderboard or any comparison with other users. This is a private journey.
The plant visualization must render correctly in both light and dark mode.
All animations must respect the user's prefers-reduced-motion media query — if set, skip animations and show final state immediately.
The gamification system must be completely invisible to users who have not yet taken any actions — no empty states showing "0 seeds", no locked badge grids on day one. Show the gamification UI only after the user has earned their first seeds (i.e. after first_root badge is unlocked).
Badge unlock animations must not interrupt a practice in progress. Queue them and show on next navigation event.
